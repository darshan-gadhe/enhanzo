Every answer below is derived from what the app actually does — the SDKs in the bundle, the permissions in the merged manifest, and the requests the code makes. Each record says where the evidence came from.

Why version 7 was rejected

Meta Audience Network merges the advertising-ID permission into your manifest. Play sees it, expects Device or other IDs to be declared as collected, and finds nothing.

$ grep AD_ID app/build/.../AndroidManifest.xml
android:name="com.google.android.gms.permission.AD_ID"

Declaring that one type is the minimum fix. The other four below are also true of the app, and an incomplete declaration is the same violation found later.

Two separate identifiers. Meta Audience Network reads the Google Advertising ID to serve and measure ads, and that is genuinely shared — Meta uses it for their own targeting, so the service-provider exemption does not apply. Separately, DeviceId generates a random UUID per install and sends it as X-Device-Id so the proxy can apply fair-use limits; that one goes only to your own backend, but it is still a device ID and still collected.

Not shared, because Replicate processes on your behalf. Play excludes transfers to a service provider from "sharing". Answer no to ephemeral: the file is written to Replicate's Files API, not merely held in memory.

Step 2

Security practices

The four questions Play asks after the data types.

Is all of the user data collected by your app encrypted in transit? Yes
Do you provide a way for users to request that their data is deleted? Yes
Have you committed to follow the Play Families Policy? No
Has your app been independently validated against a global security standard? No

Encrypted in transit is yes because every request the app makes is HTTPS — the Cloudflare proxy, Replicate, RevenueCat and Meta. Deletion is yes because History has a delete action, saved edits are purged automatically after 30 days, and the privacy policy gives an address for anything device- or purchase-linked. Play will ask for a deletion URL or email: use itechcoderdev@gmail.com, the address already in the policy.

Step 3

Two answers elsewhere that must agree

  1. Advertising ID declaration. App content → Advertising ID. Answer yes, the app uses advertising ID, and tick Advertising or marketing plus Analytics. Leaving this at "no" while AD_ID sits in the manifest is the same contradiction as the one that just failed.
  2. Ads declaration. App content → Ads. Answer yes, this app contains ads. Free users see a Meta interstitial after an enhancement.

Step 4

Before you submit

  1. Host the privacy policy. It is written and generated at docs/privacy-policy.html, but GitHub Pages is still switched off, so the URL 404s. Settings → Pages → main → /docs. Play will not accept the declaration without a reachable policy URL.
  2. Paste that URL into App content → Privacy policy, and into RevenueCat's paywall footer links.
  3. Check the policy against this page. It was updated today to name the masks, the prompts and the install identifier, all of which were missing — Play rejects a declaration that disagrees with the policy.
  4. Upload a new bundle. Version code 7 carries the rejection; the next upload needs 8.
